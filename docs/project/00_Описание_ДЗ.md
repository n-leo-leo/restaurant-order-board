# Проект
## Проектная работа

### Цель

Разработать проектную документацию и презентацию для кейса автоматизированного ресторана с последующей защитой проекта.

---

### Описание / пошаговая инструкция выполнения

Необходимо:

1. Выбрать кейс автоматизированного ресторана или подготовить его.
2. Согласовать кейс с преподавателем, а также предупредить, если вы работаете в паре с другим студентом.
3. Подготовить документацию в соответствии с требованиями кейса.
4. Сделать презентацию по шаблону (прикреплён в материалах).
5. Сдать проектную документацию в чат с преподавателем.

На защиту проекта даётся 15 минут. Более подробная информация дана на вебинаре к этому занятию.

Куратор проекта указан в кейсе или определяется в ходе согласования темы проектной работы.

Проектная работа выполняется индивидуально либо в паре с одногруппником. Если планируете работать в паре, предупредите об этом руководителя курса — Иннокентия Бодрова.

---

### Проектное задание

1. Описанные бизнес-требования ко всему приложению:
   - цели проекта, не только ИТ-системы;
   - требования бизнеса (зачем это вообще);
   - метрики (как поймём, что у нас получилось);
   - бизнес-процессы (что автоматизируем).
2. Задокументированные требования к приложению (Use Case или User Story и НФТ):
   - НФТ — в любом случае;
   - Use Case — полная диаграмма UC и описание UC из MVP и первого релиза;
   - User Story — карта пользовательских историй и выделение MVP и первого релиза.
3. Спроектированная информационная модель:
   - диаграмма классов;
   - пояснения к сущностям предметной области.
4. Спроектированная компонентная архитектура:
   - обоснование выбора архитектурного стиля;
   - диаграмма компонентов;
   - перечень интеграций;
   - схема и описание интеграции.
5. Спроектированный API:
   - описание ресурсов и эндпоинтов (бизнесовое);
   - Swagger / YAML / XSD / ProtoBuff;
   - описание UI и его взаимодействия с API.
6. Декомпозированные до задач требования:
   - DoD, DoR, Acceptance Criteria и задачи для MVP и первого релиза.
7. Описание критериев готовности и проверки требований:
   - полностью тест-кейсы для задач MVP;
   - заголовки тест-кейсов для задач первого релиза.

#### Первый подход (опционально)

1. Описанные бизнес-требования ко всему приложению.
2. Задокументированные требования к приложению (Use Case или User Story и НФТ).
3. Спроектированная информационная модель.

---

### Документирование

1. Документирование требований. Если неясно, как писать, посмотреть структуру:
   - техническое задание на систему по ГОСТ 34;
   - структура требований по стандарту IEEE 29148-2018.
2. Проектная документация:
   - Google Doc;
   - Confluence / Notion / Coda / Yonote;
   - Git + MKDocs.

---

### Рекомендации

1. Описывать от общего к частному.
2. Проверять орфографию, шрифты и цветовые обозначения. Оформление — это лицо работы.
3. Проверять прямые зависимости и делать трассировки.
4. Тестировать требования и проверять совместимость.
