# Внешние системы и интеграции

Требуемые возможности перечислены отдельно от подтвержденных свойств поставщиков. В материалах нет спецификаций конкретных продуктов и оборудования. Все контракты ниже — условия проектируемого решения. Внутренний адаптер не может компенсировать отсутствие атомарности или надежной идентификации операции у владельца данных.

## Реестр

| ID | Система, компонент и релиз | Обмен и владелец результата | Интерфейс и сбои |
|---|---|---|---|
| I-01 | Склад; C-01/C-03; MVP | Остатки, сроки годности, версия/актуальность; атомарный резерв состава, его закрепление, освобождение и состояние | REST HTTPS через адаптер. Неизвестная доступность запрещает оплату. Неизвестный резерв сверяется по исходному ID |
| I-02 | Эквайринг/терминал; C-04; MVP | purchaseId, attemptId, сумма, валюта; результат и внешний ID. Деньги проводит провайдер | REST на границе приложения, SDK терминала при необходимости. Неизвестный исход проверяется каждые 10 с; через 1 мин менеджер |
| I-03 | Роботы и ячейки; C-05; MVP | jobId, состав, тип упаковки, версия техкарты, резерв; принятие/готовность/ошибки, размещение, дверца, вес, исправность, назначение и срок | REST через адаптер. Повтор jobId не повторяет приготовление. Пропущенное состояние восстанавливается запросом |
| I-04 | Кассовая система; C-06/C-04; MVP | ID исходного расчета, позиции, скидки, сумма и вид операции; подтверждение, ссылка на чек | Касса формирует документ и взаимодействует с ОФД. Неизвестная операция сверяется; повторная оплата запрещена |

| I-06 | Внешний монитор комплекса; внешнее производство; MVP | Ошибки, состояние, потребность пополнения; порог запаса ниже 30% | Работа сотрудника во внешнем интерфейсе. Его наличие и свежесть требуют подтверждения A-05 |
| I-07 | Лояльность; C-09; первый релиз | Профиль, баланс, операции списания/начисления/отмены, резерв бонусов | REST через адаптер. Операции повторяются с прежним ID; сбой не должен удваивать бонусы |
| I-08 | SMS; C-09; первый релиз | Телефон и одноразовое подтверждение для лояльности, результат отправки | REST HTTPS. Сбой не мешает покупке картой без лояльности; SMS о готовности не добавляется |
| I-09 | 1С; C-10; первый релиз | Операции A-13 после закрытия дня, ID, суммы и возвраты; подтверждение приема | REST через адаптер; формат полезной нагрузки согласуется на этапе 3. Сбой не останавливает продажи |
| I-10 | Наличное устройство; C-04; первый релиз | Внесение, сдача, возврат неполной суммы, состояние | SDK и возможности проверяются по A-11. Неизвестный возврат блокирует следующую оплату |

ОФД не предполагается прямым адресатом приложения. Маршрут подтверждает поставщик кассы. Внешние кассовые и платежные сроки хранения не заменяются сроками приложения.

## Общие правила обмена

Каждая изменяющая операция содержит постоянный ID и корреляцию с покупкой. Повтор сохраняет ID. Тайм-аут означает неизвестный исход, а не право создать новую независимую операцию. Успех принимается только после проверки подлинности источника, ID, суммы и допустимого состояния. Соединения шифруются, роли и устройства проверяются на сервере.

Отмена передается комплексу по исходному jobId и назначению ячейки. Требуется подтверждаемый запрет еще не начатого задания и дальнейшей выдачи. Комплекс должен помнить такой запрет и при запоздавшей доставке исходного задания. При неизвестном результате запрета менеджер продолжает разбор; приложение не объявляет физическую остановку выполненной. Это дополнительное условие контракта I-03 по A-12.

Событие содержит ID источника, ID операции и номер версии/последовательности. При разрыве потока состояние перечитывается у владельца. Если владелец не поддерживает версии, требуется иной доказуемый механизм согласования порядка. Простое сравнение часов устройств недостаточно.

Для определения свежести склад должен предоставлять сигнал актуальности и срок пригодности данных. Точный интервал контроля выбирается по спецификации и испытанию, а не объявляется установленным. Истечение срока годности обрабатывается таймером. Ошибка сразу блокирует новый платеж; после 10 с без успешной проверки показывается недоступность. Успех технической проверки не снимает A-15.

Запрет новых продаж не прекращает сверку начатых операций и попытки выполнить оплаченные заказы. Доставка повторяется с тем же ID с контролем нагрузки; после исчерпания автоматического интервала вмешивается сотрудник, операция остается на контроле.

## Проверка технических допущений {#verification}

| Допущение | Необходимое доказательство | Критерий проверки | Если не выполнено |
|---|---|---|---|
| A-02 | Спецификация комплекса и стенд ячейки | Размещение увеличивает вес; чужой/истекший талон не открывает; частичное извлечение не освобождает; события восстанавливаются; неисправность блокирует; срок действует при разрыве связи | Автоматическая выдача не доказана. Изменить оборудование или отдельно пересмотреть A-02/НФТ-20 и связанные AC |
| A-03 | Доступные средства эквайринга и кассы, учетные записи менеджера | По ID исходной операции получен подтвержденный полный возврат и результат кассы; отметка сотрудника не принимается за успех | MVP не завершает проблемную покупку. Изменить внешний порядок или поставщика |
| A-05 | Демонстрация внешнего монитора | Видны роботы, ошибки, потребность пополнения и устаревание данных | Пересмотреть пилот; US-32/33 не переносить в MVP автоматически |
| A-08 | Контракт резерва и конкурентный тест | Последний комплект получает один заказ; резерв всего состава атомарен; неизвестный платеж удерживает его; повтор ID не дублирует | БТ-04/М-09 не обеспечены. Собственный резерв поверх неуправляемого склада проблему не решает |
| A-14 | Контракт кассы, SDK/стенд принтера | Потеря ответа не повторяет расчет; чек находится по исходной операции; тот же талон восстанавливается после проверки покупки | Требуется изменение интеграции/оборудования или отдельный пересмотр требований |
| A-07/НФТ-10 | Эквайринг и комплекс | После потери ответа находится исходный платеж/jobId, повтор не вызывает второго списания/приготовления | Реальный пилот не готов; внутренний outbox не доказывает внешнюю однократность |

Статус перечисленных возможностей: технические допущения, не подтверждены спецификациями или испытаниями. Для учебного проекта они задают необходимые условия реализуемости. Проверка реального оборудования — обязательное условие запуска, а не основание выдать неподтвержденную возможность за факт.

Для A-02 стенд определяет диапазон пустого веса с постоянным поддоном, погрешность, стабилизацию и тайм-аут. Испытания включают минимальную порцию, разное положение, температуру и упаковку. Успех датчика не подтверждает состав пакета или чистоту.

Резерв A-08 не продлевает годность. При длительной сверке платежа резерв остается связанным с покупкой, но пригодность проверяется снова. Если оплату подтвердили после утраты пригодности и выполнить заказ нельзя, применяется полный возврат A-12. М-09 учитывает такие случаи как отклонение, а не исключает их из статистики.
