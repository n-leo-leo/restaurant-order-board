# Глоссарий

Значения терминов, которые используются в проекте. Подробные условия и числовые показатели приведены в связанных разделах требований.

## Проект и требования

| Термин | Значение | Где используется |
|---|---|---|
| MVP | Первая рабочая версия с функциями, необходимыми для оформления, оплаты и получения заказа. | [Карта историй](02_requirements/story-map.md) |
| Первый релиз | В этом проекте — следующее расширение после MVP. Оно добавляет новые функции к уже работающей системе. | [Карта историй](02_requirements/story-map.md) |
| Пользовательская история (User Story, US) | Описание потребности пользователя: кто хочет выполнить действие и для чего. | [Пользовательские истории](02_requirements/user-stories.md) |
| Нефункциональные требования (НФТ) | Требования к качеству работы системы: скорости, доступности, сохранности данных, безопасности и удобству. | [НФТ](02_requirements/nfr.md) |
| Допущение | Условие, принятое при проектировании, если в исходных материалах нет точного ответа. | [Ограничения и допущения](02_requirements/assumptions.md) |
| Ограничение | Условие, которое задает границы решения: например, бюджет, срок или исключенная функция. | [Ограничения проекта](01_business/goals.md#_5) |

## Ресторан и заказ

| Термин | Значение | Где используется |
|---|---|---|
| Киоск самообслуживания | Устройство в ресторане, на котором гость выбирает блюда, оформляет и оплачивает заказ. | [Роли и границы системы](01_business/scope.md) |
| Табло выдачи | Экран для гостей с номерами заказов и статусами «Готовится» и «Готов». | [Приготовление и выдача](01_business/processes.md#2) |
| Ячейка выдачи | Отделение роботизированного комплекса, куда помещается готовый заказ. Гость открывает его своим талоном. | [Приготовление и выдача](01_business/processes.md#2) |
| Свободная ячейка | Исправная закрытая ячейка, доступная для нового заказа. Датчик веса должен подтвердить, что она пуста. | [Контроль пустоты ячейки](02_requirements/assumptions.md#_3) |
| Датчик веса | Устройство, которое измеряет нагрузку в ячейке. Система использует его показания для проверки размещения заказа и освобождения ячейки. | [Контроль пустоты ячейки](02_requirements/assumptions.md#_3) |
| Талон | Документ с номером заказа и кодом для получения. Номер помогает найти заказ, код позволяет открыть назначенную ячейку. Повторная печать по A-14 сохраняет тот же номер и код и не создает новый заказ. | [Оформление и оплата](01_business/processes.md#1) |
| Фискальный чек | Документ о расчете, который формирует внешняя кассовая система. Он отличается по назначению от талона; оба документа могут быть напечатаны на одном листе. | [Внешние системы](01_business/scope.md#_4) |
| Торговый день | Период работы ресторана от открытия до закрытия торгового дня. Используется для учета продаж и применения изменений меню. | [Управление меню](01_business/processes.md#4) |
| Технологическая карта (техкарта) | Описание состава блюда и параметров его приготовления. | [Пользовательские истории](02_requirements/user-stories.md) |
| Комбо-набор | Предложение из нескольких готовых блюд. Не предполагает самостоятельного изменения состава блюда гостем. | [Управление меню](01_business/processes.md#4) |
| Резерв ингредиентов | Закрепление ингредиентов за заказом перед оплатой, чтобы их не продали другому гостю. | [Ограничения и допущения, A-08](02_requirements/assumptions.md) |
| Атомарное резервирование | Резервирование за одну неделимую операцию: все необходимые ингредиенты закрепляются за заказом либо резерв не создается. | [Ограничения и допущения, A-08](02_requirements/assumptions.md) |

## Статусы и ситуации

| Термин | Значение | Где используется |
|---|---|---|
| «Готовится» | Оплаченный заказ принят роботами в работу. Отображается на табло. | [Приготовление и выдача](01_business/processes.md#2) |
| «Готов» | Заказ находится в исправной ячейке и доступен для получения. Отображается на табло. | [Приготовление и выдача](01_business/processes.md#2) |
| «Выдан» | Гость открыл ячейку действительным талоном, закрыл дверцу, а исправный датчик подтвердил пустоту. Номер снимается с табло. | [Ограничения и допущения, A-02](02_requirements/assumptions.md) |
| «Проблема» | Внутренний статус заказа, для которого требуется помощь менеджера. Сам статус гостю на табло не показывается, номер скрывается. | [Проблема приготовления или выдачи](01_business/processes.md#_1) |
| Неявка | Гость не забрал готовый заказ за отведенное время. Заказ не считается выданным. | [Ограничения и допущения, A-04](02_requirements/assumptions.md) |
| Неизвестный результат оплаты | Платеж начат, но система еще не получила подтверждение успеха или отказа. Требуется проверка предыдущей попытки до повторной оплаты. | [Оформление и оплата](01_business/processes.md#1) |
| Отмена заказа | Прекращение выполнения заказа. Результат возврата денег учитывается отдельно. | [Помощь, отмена и возврат](01_business/processes.md#5) |
| Возврат денег | Операция возврата оплаты гостю. Считается выполненной после подтверждения внешней системы. | [Помощь, отмена и возврат](01_business/processes.md#5) |

## Показатели работы системы

| Термин | Значение | Где используется |
|---|---|---|
| Медиана | Значение в середине упорядоченного списка измерений. Не менее половины измерений не превышают медиану. | [Метрики](01_business/metrics.md) |
| p95 | Время, в которое укладываются не менее 95% измерений. Оставшиеся случаи могут занимать больше времени. | [НФТ](02_requirements/nfr.md) |
| RPO — допустимая потеря данных | Показывает, за какой последний период изменения данных могут быть потеряны при сбое. RPO = 0 означает отсутствие допустимой потери подтвержденных записей. | [НФТ](02_requirements/nfr.md) |
| RTO — время восстановления | Допустимое время, за которое работа системы должна быть восстановлена после сбоя. Начало отсчета и виды сбоев задаются в требованиях. | [НФТ](02_requirements/nfr.md) |
| Доступность | Доля времени, когда система позволяет выполнить нужные действия. В проекте проверяется возможность оформить и оплатить заказ картой в часы работы ресторана. | [НФТ](02_requirements/nfr.md) |
| Пропускная способность | Количество заказов, которое система может обработать за заданный период. | [Метрики](01_business/metrics.md) |

## Внешние системы

| Термин | Значение | Где используется |
|---|---|---|
| Роботизированный комплекс | Внешняя система приготовления и выдачи, включающая роботов, ячейки и их оборудование. | [Роли и границы системы](01_business/scope.md) |
| Эквайринг | Банковская услуга приема оплаты картой. В проекте приложение получает от платежной системы результат операции. | [Оформление и оплата](01_business/processes.md#1) |
| ККТ — контрольно-кассовая техника | Кассовое оборудование, которое формирует фискальные документы о расчетах. | [Внешние системы](01_business/scope.md#_4) |
| ОФД — оператор фискальных данных | Внешний сервис обработки фискальных данных кассы. | [Внешние системы](01_business/scope.md#_4) |
