# Чек-лист приемки

Пункты используются при ревью документации и приемке реализации. Статус документации и фактическое прохождение тестов фиксируются отдельно. Все испытания приложения и оборудования пока **не выполнялись**; наличие кейса не означает приемку.

## Состав и связи {#scope-checks}

| ID | Проверка | Основание / доказательство |
|---|---|---|
| CL-01 | MVP содержит киоск, карту, талон/чек, кухню, табло, безопасную выдачу и минимальную помощь; R1 содержит согласованное расширение | [Карта историй](../02_requirements/story-map.md), БТ-12, US-01–35 |
| CL-02 | Мобильное приложение, конструктор блюда, история, повтор заказа и отзывы не включены в текущую поставку | Карта историй; метки x-release в OpenAPI; [AC](../06_decomposition/acceptance-criteria.md) |
| CL-03 | Каждая история имеет AC, конкретные задачи с результатом и зависимостями и проверки своего релиза | [Матрица](../08_traceability.md); нет висячих ID и циклов задач |
| CL-04 | Состояния и владелец данных совпадают в процессах, модели, экранах, API и тестах | [Состояния](../03_model/order-states.md), [UI](../05_api/ui.md), [контракты](../05_api/adapter-contracts.md) |
| CL-05 | Готовые разделы имеют один источник в published; навигация, якоря, схемы и таблицы доступны в обеих строгих сборках | `scripts/check_stage3.py`, `scripts/check_stage4.py`; архив сохранен |

## Фиксация результата

Для испытания указываются сборка, окружение, дата, исполнитель, фактические результаты шагов и доказательства. Непрохождение связывается с дефектом, AC и задачей. После исправления повторяются затронутые и зависимые проверки. Итоговая приемка требует выполнения [DoD](../06_decomposition/dor-dod.md) и закрытия обязательных допущений; расчет, имитатор и успешная сборка документации не заменяют испытание реализации.
