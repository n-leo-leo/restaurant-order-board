# Интерфейсы и взаимодействие с API

Экраны покрывают [истории](../02_requirements/user-stories.md) в границах их релизов. Суммы, доступность и разрешенные действия поступают с сервера. В таблицах используются `operationId` из [OpenAPI](openapi.yaml); ошибки и правила повторов определены в [ресурсах](resources.md). Кнопка оплаты становится доступной только после показа актуального расчета и явного согласия гостя.

## Общие состояния

При загрузке экран показывает название операции и индикатор. До ответа кнопка повторной отправки заблокирована. Если ответ потерян, запрос повторяется с исходным ключом. При ошибке пользователь видит сообщение, correlationId и способ продолжить работу. Технический стек скрыт. Пустой список показывается только при актуальных данных. При потере связи выводится ошибка. При ошибке доступа экран скрывает защищенные данные и предлагает сотруднику войти.

Таймер 2+2 мин, передача X-Interaction-At и условия очистки определены в [правилах сессии](resources.md#access). При processing/unknown оплаты сброс запрещен. После перезапуска киоск выполняет [восстановление сессии и покупки](resources.md#retries), затем выбирает K-03/04/05/06 по сохраненному состоянию. Кнопка завершения зависит от `getSession.allowedActions`, а не от локального таймера. Помощь менеджера доступна на гостевых экранах; отдельный чат не добавляется.

Меню и табло опрашиваются раз в 0,5 с активного экрана. 304 сохраняет содержимое при успешной проверке актуальности. При потере актуальности табло скрывает номера и показывает «Данные временно недоступны. Обратитесь к менеджеру». На киоске оплата блокируется сразу после ошибки необходимой проверки; через 10 с без успешной проверки показана недоступность продаж. Ручная остановка отображается сразу с причиной.

При not_started возвращает гостя к K-03 для нового резерва и согласия. |
| K-05 Результат и документы / гость | Сохраненные номер, сумма и результат оплаты; отдельно чек и талон | getPurchase и getSession. «Печатаем чек и талон» → «Заберите документы». endSession доступен только при разрешении сервера и свободном терминале | Сбой документа → K-06; ожидание — тот же экран. Отсутствие покупки требует восстановления, а не пустого успешного результата. Печать не блокирует кухню |
| K-06 Помощь после оплаты / гость | Номер при наличии, этап проблемы, просьба обратиться к менеджеру, статус принятия | getPurchase.documents.problemStatus показывает принятие проблемы; getSession.allowedActions разрешает endSession после талона либо принятия проблемы и безопасного освобождения терминала. Повторной оплаты нет | Менеджер открывает связанную покупку в S-02. Без связи остается безопасный экран помощи. Отмена и возврат не обещаются до подтверждения |
| K-07 Продажи приостановлены / гость | Причина остановки или недоступности, помощь менеджера | getSalesState. Новая сессия и запуск оплаты недоступны. Неоплаченная корзина сбрасывается после сообщения, резерв освобождается | Успешная техническая проверка без manualStop → новая K-01. Начатая оплата остается в K-04/06, оплаченная — K-05/06. Без связи повтор оплаты не предлагается |

Основной путь: K-01 → K-02 → K-03 → K-04 → K-05 → табло B-01 → ячейка B-02. Карточку можно пропустить, добавив блюдо из каталога. Тип обслуживания обязателен до платежа. Повторное оформление после отказа не создает новый платеж автоматически.

10 минут начинаются с первого подтвержденного показа номера в «Готов», а не с завершения приготовления. Значения firstReadyAt/expiresAt сохраняются даже после скрытия. Уборка остатка не считается получением гостем.

Процент для экрана усекается до сотых. При 29,99% показаны 29,99% и «Нужно пополнить», при 30% — «Достаточно». Признак needsRefill рассчитывает сервер до форматирования. Нет роботов — сообщение. Ошибка/устаревание — явная пометка asOf/fresh, неизвестная оценка не выдумывается. В MVP этот сценарий во внешнем мониторе A-05 |
| R-08 Продажи и 1С / аналитик, US-34 | Ресторан, период; число оплаченных, суммы до скидок, скидки, деньги, бонусы, подтвержденные возвраты и итог; пакет закрытого дня | getSalesReport → Report; createExport → Export; getExport → подтверждение/ошибка передачи | from<to. Выбор дня выгрузки меняет только сведения о пакете. Итог включает все подтвержденные операции периода, в том числе позднюю оплату. Для выбранного закрытого дня в createExport передается его tradingDayId. Экспорт использует постоянные ID операций. Пустой отчет — нули. 1С недоступна — сохраненный пакет на контроле, продажи продолжаются. Повтор ключа возвращает исходный пакет.
