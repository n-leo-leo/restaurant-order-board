# Готовность к работе и завершенность

DoR определяет готовность задачи к разработке. DoD определяет завершенность ее реализации. Поведение истории принимается по [AC](acceptance-criteria.md), а не по факту закрытия задач. Эти условия применяются к MVP и первому релизу в их границах.

## Definition of Ready (DoR)

- Указаны US, релиз и AC. Результат задачи можно проверить. Границы совпадают с картой историй.
- Определены роли, данные, состояния и допустимые переходы. Есть экран или причина его отсутствия; для обмена есть контракт операции или адаптера.
- Описаны успешный результат, отказ, неизвестный исход и восстановление. Для изменяющих команд заданы ключ повтора и проверка версии.
- Известны зависимости и способ их проверки. Внешняя возможность либо подтверждена протоколом, либо явно отмечена допущением с условием проверки.
- Для MVP подготовлены данные, шаги и ожидаемые результаты тестов. Для R1 есть заголовки; до разработки конкретной задачи они раскрываются в полные кейсы.
- Нет нерешенного вопроса, меняющего результат задачи. Разработку на имитаторе можно начать до подтверждения поставщика; допуск к интеграции и запуску требует подтвержденного контракта и протокола испытаний.

## Definition of Done (DoD)

- Результат реализован в согласованном релизе и прошел ревью кода и контрактов. Изменения модели, API и экранов согласованы между собой.
- Связанные AC проверены на согласованном стенде. Протокол содержит версию сборки, окружение, данные, фактические результаты, дату и исполнителя. Ошибки и ограничения зарегистрированы.
- Подтверждены права, изоляция ресторанов и сессий, аудит; секреты и карточные реквизиты не попадают в ответы и журнал.
- Для затронутых команд проверены повторы, потеря ответа, конфликт версии и восстановление. Внешний успех не заменен ручной отметкой. Подтвержденные данные сохраняются.
- Затронутые НФТ проверены по [плану испытаний](../07_testing/test-cases-mvp.md#nfr-tests); для R1 также по [заголовкам проверок](../07_testing/test-cases-r1.md). Допущения оборудования закрыты протоколами перед запуском.
- Нет открытого дефекта, нарушающего AC или обязательное НФТ. Принятые ограничения не расширяют MVP и отражены в требованиях и тестах.
- Обновлены документация и трассировка; обе строгие сборки, ссылки, ID и проверки связей проходят. Готов способ развертывания и восстановления затронутого результата.

## Приемка истории и релиза

История готова к приемке после DoD всех ее задач и проверки всех AC. Релиз допускается к пилоту после сквозных проверок, обязательных НФТ и подтверждения необходимых внешних возможностей. Для НФТ-19 требуется организационная проверка с сотрудниками ресторана. Приемка заказчиком и результаты испытаний фиксируются отдельно.

[Тест-кейсы](../07_testing/test-cases-mvp.md) описывают запланированные проверки. Статус «не выполнен» не соответствует DoD реализации.
