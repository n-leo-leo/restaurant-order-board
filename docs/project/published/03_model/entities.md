# Сущности и ограничения данных

## Общие правила

Внутренние идентификаторы — UUID. purchaseId создается до обращения к банку. Публичный номер присваивается после подтвержденной оплаты и уникален в пределах ресторана и торгового дня. Номер не дает права открыть ячейку. Профиль гостя для покупки необязателен.

Время событий хранится с часовым поясом. Бизнес-ланч рассчитывается по локальному времени ресторана: понедельник–пятница, с 10:00 включительно до 16:00 исключительно. Торговый день — отдельная запись. Поздние результаты не меняют день исходного заказа. Возврат учитывается датой подтверждения со ссылкой на него (A-13).

Суммы хранятся в целых копейках. Количество порций — положительное целое; ингредиентов — точное десятичное число с единицей измерения. Расчетное решение: скидка округляется до копейки на позиции по арифметическому правилу, итог равен сумме позиций. Размер 10% и исключения A-01 сохраняются.

## Ресторан и каталог

| Сущность | Ключевые данные | Ограничения и владелец |
|---|---|---|
| Restaurant | ID, название, часовой пояс, ручная остановка, причина, автор и время | Приложение. Остановка переживает перезапуск |
| TradingDay | ID, ресторан, дата учета, открытие/закрытие, версия меню | Не более одного открытого дня на ресторан. Закрытие не удаляет незавершенные операции |
| Device | ID, ресторан, тип, версия ПО, последнее соединение | Киоск, табло или терминал сотрудника |
| MenuVersion | ID, версия, состояние, состав и правила | Примененная версия неизменяема; изменения вступают со следующего дня |
| Category, Dish | ID, название, описание, состав для гостя, масса, аллергены, ссылки на фото | Приложение; категория задает порядок показа |
| MenuEntry | ID, версия меню, блюдо, категория, цена, версия техкарты, тип обычное/комбо | Приложение. Доступность не заменяет резерв |
| RecipeVersion, RecipeLine | ID, версия, ингредиент, количество, единица, параметры для кухни | Приложение хранит согласованную версию. Опасные операции выполняет внешний комплекс |
| IngredientRef | Внешний ID, название, единица | Склад владеет партиями, остатками и сроками годности |
| ComboLine | Комбо, блюдо-компонент, количество | Только готовые блюда, без циклов и изменения состава гостем |
| PromotionRule | ID, версия, период, размер, условия, исключения | MVP — фиксированный бизнес-ланч; редактор — первый релиз |

Проекция доступности содержит ресторан, позицию, результат, версию/момент исходных данных и признак актуальности. Неизвестная актуальность запрещает продажу. Истечение годности запускает пересчет без ожидания новой продажи. Для комбо проверяются все компоненты. Источник истины по запасам и резервам — складской/производственный контур.

## Покупка, оплата и документы

| Сущность | Ключевые данные | Ограничения |
|---|---|---|
| Session, Cart, CartLine | ID сессии, киоск, активность, позиции, количества, тип обслуживания | Пустую корзину оплатить нельзя. До оплаты предупреждение через 2 мин, сброс еще через 2 мин |
| Order | purchaseId, ресторан, день, киоск, номер, тип обслуживания, версия меню, суммы, состояние, версия записи | Снимок сохраняется до платежа. Изменения меню не меняют покупку |
| OrderLine | ID, название, исходная позиция, количество, цена, скидка, сумма, версия техкарты, состав комбо | Снимок состава и расчета неизменяем после запуска платежа |
| Reservation | ID, внешний ID, покупка, состав, состояние, срок до оплаты | Не более одного действующего на покупку. До платежа — 5 мин; неизвестный платеж удерживает резерв |
| PaymentAttempt | ID, покупка, резерв, способ, сумма, валюта, внешний ID, состояние, начало/результат, следующая сверка | Запись до обращения к провайдеру. Не более одной незавершенной попытки на покупку и терминал |
| Refund | ID, покупка, успешная оплата, полная сумма, причина, внешний ID, состояние, подтверждение | MVP — внешние средства; первый релиз — запуск из приложения. Отметка сотрудника не заменяет подтверждение |
| FiscalOperation | ID, вид продажа/возврат, покупка, возврат при наличии, внешний ID, состояние, ссылка на чек | Документ формирует внешняя касса. Полные фискальные данные остаются у нее |
| PrintTask | ID, документ/талон, принтер, состояние, попытки, результат | Не менее одной ссылки на печатаемый объект; при общем листе — обе. Повтор не повторяет расчет |

Снимок до оплаты включает состав и количества, тип обслуживания, цены, правила скидок, итог, purchaseId, attemptId и reservationId. После безопасного завершения платежа расчет проверяется заново. Если изменились состав, цена, скидка или итог, создается новая покупка, прежняя остается в истории. Если снимок не изменился и подтвержден отказ, новая попытка использует тот же purchaseId после проверки резерва. Сумма фиксируется на попытку; прежние попытки и их снимки не переписываются.

Внешний платеж уникален по провайдеру и внешнему ID. Ответ сверяется с покупкой, суммой и валютой. Несовпадение вызывает проблему, кухня не запускается. Сервер вычисляет сумму самостоятельно. Повторный ответ использует сохраненный результат. Успешный платеж один; повторная попытка до сверки запрещена.

## Кухня, выдача и помощь

| Сущность | Ключевые данные | Ограничения |
|---|---|---|
| KitchenJob | jobId, покупка, снимок задания, внешний ID, принятие/завершение, результат доставки | Одно логическое задание. Повтор доставки сохраняет jobId; переключение роботов не повторяет приготовление |
| RobotRef | Внешний ID, ресторан, состояние и свежесть | Исполнение и безопасность — внешний комплекс; собственный монитор — первый релиз |
| CellRef | Внешний ID, ресторан, дверца, исправность, занятость, версия состояния | Неизвестное состояние исключает ячейку из распределения. Пустота не доказывает чистоту |
| CellAssignment | ID, покупка, ячейка, начало/конец, размещение, firstReadyAt, expiresAt | Одно активное назначение на ячейку и заказ. expiresAt = firstReadyAt + 10 мин, скрытие не продлевает срок |
| Ticket | ID, покупка, защищенный код, состояние | Один код заказа; проверка активной ячейки обязательна. После выдачи, отмены и срока недействителен |
| Problem | ID, покупка и/или ячейка, этап, причина, состояние, сохраненный этап заказа, ответственный, результат | Хранится на сервере. Решение проблемы не означает возврат денег |
| Notification | ID проблемы, получатель/роль, создание, доставка, принятие | Звук и выделение до принятия; НФТ-19 — от доставки до принятия |
| Employee, Role | Личная учетная запись, ресторан, роли, состояние доступа | Менеджер — проблемы и заказы; сотрудник зала — обслуживание ячеек |
| AuditEvent | Время, операция, источник/сотрудник, старое/новое состояние, корреляция | Без реквизитов карты, кода талона и полного телефона. Технический журнал — 90 дней |
| DeliveryTask | ID операции, получатель, данные/ссылка, попытки, следующая попытка, результат | Сохраняется одной транзакцией с бизнес-изменением. Незавершенные задачи не удаляются по сроку успешных сообщений |

По A-14 повторно печатается тот же код. Для этого хранится зашифрованное значение с ограниченным доступом, отдельно — представление для проверки. Код не возвращается публичному табло. Формат и протокол проверки уточняются на этапе 3.

Выдача требует подтверждения размещения и увеличения веса, открытия действительным талоном, закрытия и стабильной пустоты исправным датчиком. Уборка сотрудником не считается получением гостем. Чистота проверяется по регламенту отдельно от датчика.

## Первый релиз

| Сущность | Данные и правила |
|---|---|
| LoyaltyProfileRef | Внешний ID, необходимые данные, последняя активность. Имя, телефон, дата рождения; email по желанию. После 12 месяцев неактивности удаление/обезличивание и разрыв связи с заказами |
| BonusOperationRef | Внешний ID, заказ, вид, количество, результат. 1 бонус = 1 руб.; списание до 30% после скидок; начисление 5% денег с округлением вниз |
| GiftAllocation | Заказ, основание, стакан, резерв. Строго больше 1500 руб. после скидок до бонусов либо специальное комбо. Только при наличии |
| ExportBatch, ExportLine | Ресторан, день, операции, постоянные ID, состояние и попытки передачи в 1С. Повтор не удваивает продажу |

Баланс — во внешней лояльности. Полный возврат отменяет начисление и восстанавливает списание (A-10). Частичные возвраты не добавляются.

## Сроки хранения

Сохраняются 90 дней технического журнала, 30 дней копий и 12 месяцев неактивности профиля. Пятилетняя история заказов — сценарий расчета емкости, а не новый срок хранения. Сроки заказов, платежных ссылок и бизнес-аудита утверждаются перед реальным запуском. Незавершенные операции и необходимые им данные не удаляются.
