# Практика обработки незабранных заказов

Дата проверки: 14.11.2026. Цель: подготовить решение для этапа 1. Ниже — практика конкретных стран и каналов заказа; она не является единым стандартом всех ресторанов или утвержденным правилом нашего проекта.

## Вывод для проекта

Нужно различать неявку за готовой едой, незавершенный предзаказ и невозможность исполнения по вине ресторана. По опубликованным примерам нельзя установить единый отраслевой срок хранения. Можно использовать принцип: готовая еда доступна ограниченное время, далее персонал освобождает место выдачи по регламенту.

Предложение для учебного MVP, **согласовано с автором проекта 14.11.2026; подтверждение технолога и преподавателя не зафиксировано**:

1. Отсчитывать срок доступности с момента готовности и появления номера на табло.
2. Взять 10 минут как предварительное проектное допущение по примеру McDonald’s в Дании, а не как подтвержденный безопасный срок для наших блюд.
3. По истечении срока уведомлять сотрудника для освобождения ячейки и утилизации по ресторанному регламенту. Не считать ячейку свободной, пока еда фактически не удалена.
4. Не автоматизировать возврат или повторное приготовление только из-за неявки гостя. Порядок обработки обращений фиксируется отдельно; правило возврата при сбое ресторана остается самостоятельным.
5. Согласовать срок с технологом и возможностями ячеек; до этого не объявлять его окончательным. Детекция фактического получения гостем в MVP не требуется.

Открыто: выбор срока, исполнителя и способа уведомления, правила удаления номера с табло и связь этого события со статусом заказа.
