# restaurant-order-board
Проектная работа: приложение для заказа и табло автоматизированного ресторана

Документация онлайн: https://n-leo-leo.github.io/restaurant-order-board/

## Структура репозитория

- `docs/home_work/` — исходные результаты домашних заданий и материалы курса; целиком не публикуются
- `scripts/homework-publication.json` — явный список принятых результатов для сайта с контрольными суммами
- `scripts/publication.py` — сборка отдельного раздела ДЗ без изменения исходных файлов
- `docs/project/00_Описание_ДЗ.md` — требования к проектной работе
- `docs/project/01_План_проектной_работы.md` — план и чек-лист работ
- `docs/project/documentation/` — рабочая документация: черновики, заготовки и журнал решений
- `docs/project/published/` — только проверенные материалы для отправки преподавателю; из этой папки собирается проектный раздел сайта
- `mkdocs.yml` — настройки публичного сайта
- `mkdocs.draft.yml` — настройки локального просмотра всей рабочей документации

## Как открыть документацию локально

Первый запуск (один раз): создать виртуальное окружение и установить MkDocs.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Дальше каждый раз:

```bash
source .venv/bin/activate
mkdocs serve
```

Сайт откроется по адресу http://127.0.0.1:8000. Изменения в `.md` файлах видны сразу после сохранения. Остановить — `Ctrl+C`.

Собрать статический сайт: `mkdocs build` (результат в папке `site/`).

Если `python3` не найден, macOS предложит установить Command Line Tools — согласиться, затем повторить команды.

На GitHub сайт собирается автоматически при каждом push в `main` (`.github/workflows/docs.yml`).

## Рабочая документация и публикация

Публичный сайт содержит два самостоятельных раздела: проектную документацию из `docs/project/published/` и принятые домашние задания по списку `scripts/homework-publication.json`. Хук `scripts/publication.py` собирает их во временной папке: результаты ДЗ размещаются по адресам `homework/<номер>/`, без копирования в проектную документацию. Существующие адреса проектных страниц сохраняются.

Планы, вопросы преподавателю, исследования, рабочие страницы `documentation/`, условия ДЗ и материалы курса не входят в сборку сайта, поиск и публикуемые файлы. ДЗ 17 исключено из списка и дополнительно запрещено в сборщике.

Посмотреть все рабочие разделы локально:

```bash
source .venv/bin/activate
mkdocs serve -f mkdocs.draft.yml
```

Рабочая сборка при необходимости: `mkdocs build -f mkdocs.draft.yml --strict` (папка `site-draft/`). GitHub Actions использует только `mkdocs.yml` и публикует `site/`.

### Подготовка этапа к согласованию

1. Доработать разделы в `docs/project/documentation/`, сверить их с принятыми решениями и условиями завершения этапа.
2. Скопировать подготовленные страницы в `docs/project/published/`, сохраняя структуру разделов; добавить только используемые изображения и вложения.
3. Удалить из публичной версии рабочие пометки, вопросы, пустые таблицы и заготовки. Содержательные допущения системы сохранить, если они нужны для оценки решения; формулировать их как часть спецификации.
4. Добавить страницы в `nav` файла `mkdocs.yml` и ссылки на главной странице `published/index.md`. Ссылки должны вести только на материалы публичной зоны. Не копировать целиком рабочую папку.
5. Выполнить `mkdocs build --strict`, проверить содержание, навигацию, поиск и вложения. После отправки изменений в `main` сайт обновится автоматически.

Публичная папка — отдельная версия для проверки: последующие изменения черновиков не меняют отправленный комплект, пока их явно не перенесли в `published/`. После замечаний преподавателя исправлять рабочую версию и обновлять публичную копию осознанно. При отправке ссылки удобно фиксировать дату и коммит в рабочем журнале согласований.

В публичной зоне подготовлены описание проекта, план этапов и первая версия содержимого этапа 1: бизнес-требования, процессы, истории, НФТ и допущения. Рабочие вопросы, отчеты, журнал и разделы последующих этапов не копируются. «Для согласования» не означает «уже согласовано преподавателем».

Отделение сборки не делает файлы репозитория приватными: при публичном репозитории черновики остаются доступны на GitHub. Ранее опубликованные страницы также могли сохраниться в поисковых системах или чужих копиях.

### Принятые домашние задания

В разделе опубликованы ДЗ 02–13, 15 и 16. Для ДЗ 13 выбран результат `Прогноз_нагрузки_Робот_и_точка.xlsx`, для ДЗ 15 — Markdown, PDF и изображения, для ДЗ 16 — Markdown. Учебные таблицы, SQL, кейсы, описания заданий и презентации исключены. Файлы результатов копируются без изменения содержимого; Markdown отображается средствами MkDocs.

Список публикации фиксирует SHA-256 каждого файла. Изменение исходного принятого результата останавливает сборку: обновлять список и контрольные суммы следует только после явной проверки новой принятой версии. Добавление файлов в `docs/home_work/` само по себе не публикует их. При добавлении принятой работы укажите папку, точный список результатов и SHA-256 в манифесте; ДЗ 17 не добавлять. Для новой принятой редакции сохраните предыдущие исходники отдельными файлами и добавьте новую редакцию явно, не перезаписывая архив.

Проверка перед публикацией: `mkdocs build --strict`. GitHub Actions собирает тот же раздел автоматически при push в `main`; отдельный сервис размещения не требуется.
